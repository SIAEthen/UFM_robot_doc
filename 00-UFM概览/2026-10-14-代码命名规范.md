# 机器人项目代码命名规范

> 版本：v1.0  |  适用范围：C++ / ROS 2 移动机器人项目  |  状态：团队建议规范
>
> 原则：**保留现有 C++ 命名习惯，ROS 2 专有资源遵守 ROS 约定；同一项目保持一致。**

## 1. 核心命名规则速查

| 对象                      | 规则                      | 正确示例                                          | 不推荐示例                          |
| ----------------------- | ----------------------- | --------------------------------------------- | ------------------------------ |
| C++ 类、结构体               | 大驼峰 `PascalCase`        | `KinematicsInterface`, `RobotState`           | `kinematics_interface`         |
| C++ 头文件、实现文件            | 大驼峰，主类同名                | `KDLInterface.h`, `KDLInterface.cpp`          | `kdl_interface.cpp`            |
| C++ 方法、普通函数             | 小驼峰 `camelCase`，优先动词短语  | `calcKinematics()`, `updateOdometry()`        | `Calc_Kinematics()`            |
| C++ 成员变量                | `m_` + 小驼峰              | `m_chain`, `m_jointPosition`                  | `m_chian`, `joint_position_`   |
| 局部变量、形参                 | 小驼峰                     | `jointPosition`, `timeStep`                   | `joint_position`               |
| 常量、`constexpr`          | `k` + 大驼峰               | `kMaxJointCount`, `kDefaultTimeout`           | `MAX_JOINT_COUNT`（非宏）          |
| 宏                       | 全大写下划线；仅必要时使用           | `UFM_ENABLE_DEBUG`                            | `EnableDebug`                  |
| 枚举类型                    | 大驼峰                     | `ControlMode`                                 | `control_mode`                 |
| 枚举项（`enum class`）       | 大驼峰                     | `ControlMode::Position`                       | `ControlMode::position_mode`   |
| 类型别名                    | 大驼峰                     | `JointVector`, `ClockPtr`                     | `joint_vector_t`               |
| 模板类型参数                  | 大驼峰                     | `ScalarType`                                  | `scalar_type`                  |
| C++ 命名空间                | 全小写下划线 `snake_case`     | `ufm_robot::kinematics`                       | `UFMRobot::Kinematics`         |
| 普通功能子目录                 | 全小写下划线                  | `kinematics/`, `drivers/`                     | `Kinematics/`, `Drivers/`      |
| ROS 2 包及其根目录            | 全小写下划线，字母开头             | `ufm_robot_bringup`                           | `UFMRobotBringup`              |
| 配置文件、launch 文件          | 全小写下划线                  | `nav2_params.yaml`, `robot_bringup.launch.py` | `Nav2Params.yaml`              |
| 测试 C++ 文件               | `Test` + 大驼峰主题 + `.cpp` | `TestKDLInterface.cpp`                        | `testKdl.cpp`                  |
| ROS 2 消息 / 服务 / 动作定义文件  | 大驼峰                     | `RobotStatus.msg`, `ResetOdometry.srv`        | `robot_status.msg`             |
| ROS 2 消息字段、参数、Topic、服务名 | 全小写下划线                  | `joint_position`, `/robot/odom`               | `jointPosition`, `/Robot/Odom` |
| Markdown 文档             | 推荐全小写下划线（保留已有中文文档亦可）    | `coding_standard.md`                          | 多种风格混用                         |

**优先级：ROS 2 接口及生成代码规则 > 第三方库约定 > 本项目自定义 C++ 风格。** 例如 ROS 2 生成的 `robot_status.hpp` 不要因为本规范而重命名。

## 2. 文件和文件夹

### 2.1 C++ 文件

- 一个主要类对应一组同名头文件/源文件：`KinematicsInterface.h` + `KinematicsInterface.cpp`。
- 延续现有 `.h` 和 `.cpp` 约定；**新建代码统一使用这两个扩展名**。如决定向 ROS 2 主流的 `.hpp` 迁移，应单独提出团队决策，一次性统一，避免混用。
- 缩写需固定写法：例如现有 `KDLInterface`、`IMUDriver`、`PIDController`。同一缩写不得一处 `KDL`、一处 `Kdl`。
- 入口文件如 `main.cpp` 是允许的特例；ROS 2 自动生成或生态规定的文件遵循外部约定。
- 避免 `NewClass.cpp`、`Utils.cpp`、`Test2.cpp`、`final_v3.cpp` 等含糊命名。

### 2.2 目录、仓库和 ROS 2 包

- **GitHub 仓库名**：建议全小写并以连字符或下划线分词，如 `ufm-robot-doc`、`ufm_robot_ros2`。已有 `UFM_robot_doc` 不必为风格而强制改名。
- **ROS 2 包名 / 包目录**：必须使用小写字母、数字、下划线，且以小写字母开头；例如 `ufm_robot_description`、`ufm_robot_bringup`、`ufm_robot_navigation`。
- **包内功能目录**：统一小写下划线，如 `include/`、`src/`、`config/`、`launch/`、`test/`、`docs/`、`scripts/`、`maps/`。
- **`include` 组织**：头文件置于 `include/<package_name>/` 内，避免与其他包同名头文件冲突。
- **同一仓库内不得仅靠大小写区分路径**，例如 `Control/` 与 `control/`；Windows 文件系统下很容易混淆。

### 2.3 推荐目录示例

```text
ufm_robot_ws/
└── src/
    ├── ufm_robot_description/
    ├── ufm_robot_bringup/
```

## 3. C++ 类型、方法、变量

### 3.1 类与结构体

- 名称表达**名词或名词短语**，例如 `KinematicsInterface`、`OdometryEstimator`、`MotorDriver`。
- 抽象接口可使用 `Interface` 后缀，例如 `KinematicsInterface`；具体实现名称描述实现策略，例如 `KDLKinematics`。
- 不要随意添加 `C`、`I`、`Impl` 等前后缀；`Impl` 仅限确实采用 PImpl 等设计的内部实现。

### 3.2 方法与函数

- 采用小驼峰，以动词开头：`calcKinematics()`、`updateJointState()`、`publishOdometry()`、`resetController()`。
- 查询方法：`getJointPosition()`；布尔查询：`isInitialized()`、`hasError()`、`canMove()`。
- 同一概念统一动词：若项目选择 `calc`，不要在相同接口混用 `compute` / `calculate`；除非语义确有差别。
- 使用具体名称：`updateOdometry()` 比 `processData()` 更清晰。
- C++ 构造/析构函数按语言要求与类同名，例如 `KDLInterface()`、`~KDLInterface()`，不适用小驼峰方法规则。

### 3.3 变量

- 非静态成员变量：`m_` + 小驼峰，例如 `m_chain`、`m_jointPosition`、`m_jointVelocity`。
- 普通局部变量和形参：小驼峰，例如 `jointIndex`、`targetPose`、`timeStep`。
- 静态数据成员也统一使用 `m_` 还是使用 `s_`？**本项目规定静态可变成员使用 `s_` + 小驼峰**，例如 `s_instanceCount`，与实例成员区分。
- 避免单字母名称，循环计数 `i`、`j` 和数学坐标 `x`、`y`、`z` 可例外。
- 布尔变量以状态含义命名，例如 `m_isInitialized`、`hasObstacle`。
- 包含单位的量在易混淆处带单位后缀，例如 `timeoutMs`、`distanceM`、`angularVelocityRadS`；在明确使用 SI 单位的内部算法中可省略冗余后缀，但接口、日志和配置应明确单位。

### 3.4 常量与宏

```cpp
constexpr double kDefaultWheelRadius = 0.075;
constexpr int kMaxRetryCount = 3;
#define UFM_ROBOT_VERSION_MAJOR 1  // 仅在确需预处理宏时使用
```

- 普通常量优先采用 `constexpr` / `const`，避免可用常量替代的宏。
- `enum class` 优于旧式无作用域 `enum`。

### 3.5 完整 C++ 示例

```cpp
// KDLInterface.h
#pragma once

#include <vector>

namespace ufm_robot::kinematics {

enum class SolverStatus {
    Success,
    InvalidInput,
    SolverFailure
};

class KDLInterface {
public:
    explicit KDLInterface(double timeStep);

    bool isInitialized() const;
    SolverStatus calcKinematics(const std::vector<double>& jointPosition);
    const std::vector<double>& getJointPosition() const;

private:
    static constexpr int kMaxJointCount = 12;

    double m_timeStep;
    bool m_isInitialized{false};
    std::vector<double> m_jointPosition;
};

}  // namespace ufm_robot::kinematics
```

> 注：成员变量拼写应为 `m_chain`，不是原示例中的 `m_chian`。

## 4. ROS 2 专用命名：不要照搬 C++ 文件规则

### 4.1 包和接口

| ROS 2 对象 | 规则 | 示例 |
|---|---|---|
| 包名 | `snake_case` | `ufm_robot_control` |
| `.msg/.srv/.action` 文件 | `PascalCase` | `MotorState.msg`, `SetControlMode.srv`, `NavigateToPose.action` |
| 消息字段 | `snake_case` | `wheel_velocity`, `motor_current` |
| 消息常量 | `UPPER_SNAKE_CASE` | `STATUS_READY` |
| ROS 参数名 | `snake_case`，必要时点分层 | `wheel_radius`, `controller.max_speed` |
| Topic / Service / Action 名 | 小写下划线，可用 `/` 分层 | `/odom`, `/imu/data`, `/robot/set_mode` |
| TF frame ID | 小写下划线 | `map`, `odom`, `base_link`, `laser_frame` |
| launch 文件 | `snake_case.launch.py` | `robot_bringup.launch.py` |
| YAML 文件 | `snake_case.yaml` | `nav2_params.yaml` |
| Python 文件 | `snake_case.py` | `odom_publisher.py` |

**注意**：ROS 2 接口定义文件 `MotorState.msg` 是大驼峰，但自动生成的 C++ 头文件通常是 `motor_state.hpp`。请使用生成结果，不手工重命名。

### 4.2 命名空间与机器人实例

- 节点名称使用功能名，如 `wheel_controller`、`lidar_driver`；节点命名空间用于多机器人实例，如 `/robot_01/wheel_controller`。
- 对外 Topic 名、TF 名属于系统接口，更名可能导致节点互通失败，必须同步更新 launch、参数、文档和测试。
- 遵守 ROS 的现成惯例，优先 `map`、`odom`、`base_link`，不要自行创造 `MapFrame`、`RobotBase` 等同义名称。

## 5. 文件命名的边界与特例

以下文件**不应为了统一大驼峰而重命名**：

- ROS 构建/元数据：`package.xml`、`CMakeLists.txt`。
- GitHub 与 Git：`.gitignore`、`README.md`、`CONTRIBUTING.md`、`.github/workflows/build.yml`。
- ROS 2 Python / launch / 配置：`robot_bringup.launch.py`、`nav2_params.yaml`。
- ROS 2 代码生成输出、第三方依赖和供应商驱动：遵守其原有接口与命名。

## 6. 团队执行规则

1. **新代码必须遵守本规范**；现有代码不因纯命名问题进行大规模重构，可随功能维护逐步改进。
2. **公共 API、消息字段、Topic、参数、包名的重命名属于接口变更**；应关联 Issue，并说明兼容性与迁移步骤。
3. PR 评审检查：文件名、目录名、成员变量前缀、函数动词、缩写、单位、ROS 2 接口一致性。
4. 不用含糊名称：`tmp`、`new`、`final`、`data2`、`test_final` 等。
5. 单词缩写统一维护，例如 `KDL`、`IMU`、`PID`、`TF`、`ROS`；已有公共接口优先保持兼容。
6. 推荐在仓库中搭配 `.clang-format` 统一**排版**。注意：`clang-format` 不负责强制变量命名；如果后续要自动检查命名，可另行配置 `clang-tidy` 的 `readability-identifier-naming`，先在小范围试运行，确认它支持项目约定。

### PR 命名检查清单

- [ ] 新 C++ 类名和对应源文件名使用大驼峰
- [ ] 函数使用动词短语和小驼峰
- [ ] 实例成员变量使用 `m_` 前缀和小驼峰
- [ ] 包、功能目录、launch、YAML 使用小写下划线
- [ ] 消息定义和字段分别遵守 ROS 2 的专有命名规则
- [ ] 缩写及单位表达一致
- [ ] 公共接口更名已更新调用方、文档和测试
- [ ] 不存在大小写仅差异的路径名

- ROS 2 C++ 代码风格：https://github.com/ros2/ros2_documentation/blob/rolling/source/The-ROS2-Project/Contributing/Code-Style-Language-Versions.rst
